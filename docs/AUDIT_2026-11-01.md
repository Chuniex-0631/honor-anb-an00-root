# ANB Root 源码审计增量（2026-11-01）

基线：main commit `e2b03047a58f43e3e0c56841fc17c0751394d14c`，公开正式发行 v2.2.0，Android 15 / ANB-AN00。

## 已核对范围

- Android Manifest 与权限、Shizuku UserService/Binder 调用链、执行身份、命令执行器、临时 Root 状态机、同次开机防重跑、日志与文件校验。
- Shell loader 模板、KernelSU 可选 allow_shell 参数、运行时清理/回滚流程（静态阅读）；原生 exploit / LKM 仅可进行哈希与来源核验，不能将二进制静态检查视为源码审计。
- Python 公共发布检查、归档检验、构建脚本、GitHub CI、现有 JVM 回归用例和发布元数据。

## 本次修复（未发布的审计分支）

1. **高优先级 / 固件误判**：旧 `compatible()` 仅匹配型号+内核，可能将相同 kernel 字符串的不同固件误判为受支持。新增 SDK 35 与已归档的完整 `ro.build.fingerprint` 精确比较；独立 Shizuku shell 的 `getprop` 也复核指纹。模糊匹配、其他 Android 版本和缺失信息全部 fail closed。
2. **中优先级 / 检查与启动竞态**：环境检查和恢复启动之前分别判断普通布尔值/忙碌标志，有并发窗口。用同一监视锁互斥入口，并禁止在环境检查进行中启动恢复。
3. **信息披露 / 诊断留存**：用户界面此前称诊断文件只保存在选定位置，但程序还会在 App 专属外部目录自动留下环境和验证摘要。修正文案并公开保留位置与访问边界。
4. **回归保护**：针对已验证固件、错误机型、不同内核、Android SDK、错误/缺失指纹的 8 个用例。当前核心文件清单哈希已重新固定，历史 v2.1.0 基线只豁免这两份明确变更的文件。

## 保留的发布阻断与操作边界

- **签名**：CI 只编译未签名 APK；原正式版私钥不在仓库。该分支不能自动产出与 v2.2.0 相同证书的可覆盖安装正式包，不得改名冒充官方 Release。
- **实机**：新指纹门禁与调试工具 `allow_shell=1` 分支，仍需已适配 ANB-AN00 实机复验；远端单元测试不能证明真实内核利用成功。
- **高风险 loader 失败路径**：涉及 `hisecd` 暂停与恢复、`sig_enforce`、`kptr_restrict`、SELinux 复位，某些异常退出可能中断收尾。为了避免修改已验证的内核态流程，此次未重写模板，需按实机故障注入方案验证。
- **二进制可审计性**：仓库含预编译 `exploit` 与定制 `kernelsu.ko`，哈希一致不等同于可复现构建或完整原生安全审计。
- **运行证据**：CI 可证明编译和回归测试，不能替代锁 BL、AVB green、SELinux Enforcing 和重启恢复的最新设备观测。

## 发布判断

审计分支仅供 PR/CI 验证。继续保留已签名 v2.2.0 为最新正式发行。只有使用原签名完成新 APK、验证对应哈希及上述实机项目后，才能发布下一正式版。
