# 使用指南

从 [2.4.0 正式发布页](https://github.com/Chuniex-0631/honor-anb-an00-root/releases/tag/v2.4.0) 下载 APK，并核对 [兼容范围](COMPATIBILITY.md)。**本版更换发布签名：2.3.5 及以前版本必须卸载后重装。** 使用同一新签名的 2.4.0 后续版本才可覆盖升级。

## 从旧版迁移到 2.4.0

1. **先保留旧版记录。** 在旧版“记录”页导出诊断，核对记录中的开机编号和恢复目录是否属于当前开机的尝试。恢复仍在进行时不要清除数据或卸载；等待结束，无法确认时先按故障提示完整重启。
2. **已有 Root、本次开机尝试过恢复或记录归属不明时，先完整重启。** 重启会结束临时 Root，也让下一次恢复使用新的开机记录。卸载会删除 App 私有记录，但同次开机的锁与已加载模块可能仍存在；因此不要卸载后在原开机状态强行重跑，也不要手动删除锁。
3. **卸载 2.3.5 或更早的 ANB Root，再安装 2.4.0。** Android 会拒绝不同证书的覆盖安装；该提示不能通过重复点击安装解决。无需卸载 Shizuku 或 KernelSU，也不需要清除它们的数据。
4. **重新完成准备与授权。** 启动 Shizuku，重新允许新安装的 ANB Root 访问；在 App 中重新完成首次准备并设置“允许调试工具使用 Root”（默认关闭），需要时在 KernelSU 重新给 ANB Root 授权。卸载重装不会保留旧 App 的设置和授权状态。
5. 按下面的首次使用步骤恢复并验证；如果提示缺少本次开机记录，完整重启后再操作。以后使用同一新证书发布的版本可覆盖安装并保留 App 设置。

2.4.0 新发布证书 SHA-256：`623049d5e0d4bb3806077181e4865836e925ad79d40b683a7f65c027ca04f3b2`。核对签名的方法见 [构建说明](BUILD.md)。

## 第一次使用

1. 安装官方 [Shizuku](https://shizuku.rikka.app/download/) 和 [KernelSU v3.3.0](https://github.com/tiann/KernelSU/releases/tag/v3.3.0)。
2. 在 Shizuku 中通过无线调试完成配对并启动；本工具要求 shell 模式。
3. 打开 ANB Root，允许 Shizuku 访问。按钮会引导完成缺少的准备步骤。
4. 检查通过后点“完成首次准备”；按需选择“允许调试工具使用 Root”（默认关闭），然后点“恢复 Root”。
5. 如等待授权，在 KernelSU → 超级用户中允许 ANB Root，再返回验证。

## 允许调试工具使用 Root

普通使用保持关闭。开启后，ADB、Shizuku 等所有以 shell 调试身份运行的工具可直接获准使用 Root，无需逐项授权；普通应用仍需 KernelSU 授权。开启时请阅读 App 内的说明并确认。

选择会被记住，仅在新一次恢复时生效，恢复中不能修改。已有 Root 时不能即时开关；需完整重启后，在恢复前修改。继续查看同次开机的旧尝试不会改变原参数。关闭选项不撤销 KernelSU 中其他已有授权。

开启模式的脚本分支与参数传递有自动化检查；测试与构建不代表所有模块组合均已实机验证。按版本记录的实机范围见 [验证摘要](VALIDATION.md)。

## 每次重启后

解锁手机、等待开机约 90 秒 → 重新启动 Shizuku → 回到 ANB Root 恢复。不是后台自动开机 Root。

## 页面与失败处理

- 首页：准备状态、五阶段进度与主要按钮；失败时就地显示原因与下一步。
- 记录：本地诊断、用户选择位置导出、复制记录、单独刷新 KernelSU。
- 帮助：首次使用、重启流程、问题和许可证。

管理器用于授权，本工具自动完成定制模块加载。不要并发运行其他恢复链。失败或超时先保存诊断，再按提示重新启动系统。

关闭开发者选项、无线调试或撤销配对后，需要先在手机上恢复 Shizuku 的启动条件。免电脑工作流仍需要调试授权。

## 检查与失败处理

- 机型、Android 版本、完整固件和内核全部匹配才开放恢复，同内核的其他固件也不放行。
- 开机不足 90 秒时，等待后可再点恢复；此时还没有启动载荷。
- “验证当前 Root”“检查现有进度”只检查已有模块或本次记录，不启动新恢复。
- 成功验证要求原 loader 的初始化和收尾标记齐全，并实时读回 SELinux、模块签名校验、kallsyms 挂载、内核保护参数与后台服务状态。仅出现 KernelSU 模块或 `uid=0` 不表示流程已完整成功。
- 若提示保护设置未恢复，请保存记录并完整重启；不要继续使用本次未完成的 Root。
- 若记录丢失但本次开机已有尝试，请完整重启后再恢复。超时或连接中断不表示后台载荷已经停止。
- “上次验证成功”是历史结果，需要确认此刻权限时可再次验证。
- 执行环境与验证摘要会自动写入本机 App 专属目录。手动导出诊断时由你选择保存位置，App 不会自动上传；分享前检查内容。

代码检查与模拟测试不代替手机提权及重启恢复实测；当前修复与证据范围见 [2.4.0 审计与验证](AUDIT_2.4.0.md) 及 [验证摘要](VALIDATION.md)。
