# ANB Root — UI 重构设计说明（待发布）

## 设计参考与边界

参考 KernelSU 状态首页的视觉原则：一眼可读的状态、轻量卡片、明确的次级信息、底部导航及浅色／深色表面。**不复制 KernelSU 图标、应用名称或设计资产**。ANB Root 仅负责恢复 Root，不冒充 KernelSU 的授权／模块管理器。

## 信息架构

| 页面 | 重点 | 操作 |
|---|---|---|
| 首页 | Root 状态、机型与固件、Shizuku、KernelSU、环境和进度 | 固定唯一按钮：检查／准备／恢复／验证 |
| 设置 | shell 调试工具 Root 授权、管理器刷新 | 高权限二次确认，加载后锁定 |
| 记录 | 本次状态、最近日志、完整诊断导出 | 系统文件选择器导出、安全处理说明 |

顶部“帮助”提供简短步骤；“关于和许可”在设置中。支持 Android 深色模式、系统栏安全区域处理及页面垂直滚动。

## 交互和安全规则

- `UiState.resolve()` 作为统一文案和 CTA 模型；环境未就绪的引导优先于旧的 SUCCESS。
- 检查和恢复过程中禁止再次启动恢复。失败后主按钮只重新检查环境，不伪装成只读查询却偷偷启动新的恢复链。
- 已验证时允许重新验证；加载后权限授权转至 KernelSU。后端执行前仍重新检查全部门禁。
- 调试工具 Root 授权需二次确认；恢复中／模块已加载时锁定，设置变更不代表重配当前模块。
- 记录页只渲染最近 32,000 字符；完整日志仍可导出。自动保留的诊断和暂存文件另见隐私政策。
- 不增加新 Android 权限；原始 exploit、LKM 及 loader 模板未改动。

## 验收要求

- JVM 测试覆盖各门禁、忙碌、首次准备、失败、等待授权、已验证、旧成功与断开的 Shizuku。
- GitHub Actions 使用 SDK 35 编译 APK，上传未签名工件。
- 待实机确认浅／深色、大字体、窄屏、旋转、系统手势导航、通知拒绝、日志导出、断连／恢复及实际 Root 权限恢复。
- 正式覆盖安装必须使用原签名密钥；未签名 CI 工件不可冒充官方 Release。
